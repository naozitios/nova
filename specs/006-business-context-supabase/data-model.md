# Data Model: Business Context Supabase Backend

## Storage Overview

Supabase Postgres stores tenant ownership, source metadata, extracted facts, questions, conflicts, versions, jobs, and audit records. Supabase Storage stores original uploads and retained raw payloads in private buckets. Generated Markdown is a projection only and is never the source of truth.

## Storage Buckets

- `business-context-sources`: private original uploads and retained raw snapshots. Path format: `{workspace_id}/{business_id}/sources/{source_id}/{checksum}-{filename}`.
- `business-context-archives`: private archived raw provider payloads and large derived artifacts. Path format: `{workspace_id}/{business_id}/archives/{source_id}/{artifact}`.

Storage policies must require the first path segment to match a workspace where the user has a membership. Service-role workers may read/write only server-side.

## RLS Policy Model

- Enable RLS on every tenant-owned table.
- Read policy: `exists (select 1 from workspace_members wm where wm.workspace_id = table.workspace_id and wm.user_id = auth.uid())`.
- Viewer write policy: no writes.
- Editor write policy: editors, admins, and owners may create businesses, onboarding sessions, sources, facts, questions answers, drafts, and jobs.
- Approval/restore policy: admins and owners only.
- Service-role operations bypass RLS only inside server-side ingestion/extraction/worker code; browser code never receives service-role credentials.

## Processing Stage Model

Source processing is tracked at three levels:

1. `context_sources.status` shows the current user-facing source state.
2. `context_jobs.status` controls worker scheduling, retry, locks, heartbeat, and dead-letter behavior.
3. `context_processing_runs` and `context_processing_stage_events` provide append-only operational visibility for progress, timing, attempts, failures, warnings, and cost.

Stages are linear by default: `registered -> queued -> acquiring -> stored -> parsing -> normalizing -> extracting -> reconciling -> quality_checking -> completed`. A stage may be skipped only when it is not applicable to the source type, and skipped stages must emit a `skipped` stage event with a reason.

Terminal source outcomes are exclusive:

- `processed`: all blocking quality gates passed and no material warnings remain.
- `processed_with_warnings`: blocking gates passed but non-blocking warnings exist.
- `blocked_needs_user_action`: source cannot proceed until the user labels, corrects, accepts, or replaces it.
- `failed_permanent`: source cannot be processed automatically.
- `archived`: source is removed from active processing without deleting evidence history.

## Retry, Stuck Job, and Circuit Breaker Rules

- Retryable error classes: `provider_timeout`, `provider_5xx`, `worker_oom`, `network_transient`, and `rate_limited`.
- Non-retryable error classes: `validation`, `auth`, `ssrf`, `malware`, `unsupported_file`, `budget_exceeded`, `schema_contract`, and `quota_exhausted`.
- Default backoff schedule: 30 seconds, 2 minutes, 10 minutes, 30 minutes, with +/- 20% jitter and `max_attempts = 4`.
- A running job must update `heartbeat_at` at least every 30 seconds. If `heartbeat_at` is older than 2 times `stage_timeout_seconds`, the recovery sweep marks it `stalled`.
- Retryable stalled jobs transition to `retry_waiting` with the next backoff delay. Exhausted stalled jobs transition to `dead_lettered`.
- Circuit breakers open when a provider has at least 5 failures in 10 minutes and failure rate is 50% or higher, 3 consecutive timeouts, or explicit quota/budget exhaustion. An open breaker blocks new dispatch for that provider. After `half_open_after`, one probe job may run; success closes the breaker, failure reopens it.

## Quality Gate Rules

Document gates run before extraction:

- MIME and extension allowlist passed.
- Malware scan passed or documented as unavailable in local development.
- Checksum and content hash present.
- Parser produced non-empty Markdown unless the file is intentionally metadata-only.
- Page/slide coverage is at least 90% for documents with known page or slide counts, or the run is marked `processed_with_warnings`.
- OCR mean confidence is at least 0.65 for OCR-derived documents; lower-confidence pages are flagged with evidence locators.
- Truncation did not remove required sections, or the source is blocked for user review.
- Evidence locator availability is recorded for every extracted document element when the parser supports locators.

Fact gates run before profile compilation:

- Fact value conforms to the Zod schema for its `fact_key`.
- Extracted/inferred facts include `source_id`, source excerpt, and confidence.
- Confidence >= 0.70 may be proposed when no higher-precedence conflict exists; 0.50-0.69 requires review; < 0.50 is stored as low-confidence evidence and not proposed.
- User-verified facts bypass confidence thresholds but still require source/audit metadata.
- Material conflicts block approval until resolved or explicitly marked unknown where allowed.
- Authority and effective-date metadata are present when a source claims to supersede another source.
